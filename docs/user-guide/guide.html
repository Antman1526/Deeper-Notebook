1What Deeper Notebook is

A research workspace where every answer comes from material you chose.

Deeper Notebook is a native desktop application for source-grounded research. You collect documents, audio, video, and web pages into notebooks. The application reads them, breaks them into passages, and indexes those passages. From then on, everything it produces — chat replies, syntheses, study guides, podcast scripts, slide decks — is drawn from your material and cites the passage it came from.

Two things make it different from a web research assistant:

  • It is yours. Your notebooks, sources, passage index, chat history, and the facts it remembers about you all live in a database file on your own drive, behind a password you set and an encryption key you control.
  • It works with the network cable unplugged. The application bundles its own database, its own web server, and can run its own AI models — for chat, for indexing, for transcription, and for speech. Cloud providers are supported, but they are strictly opt-in and never required.

Who it is for

Anyone who needs to work through a body of material and be able to answer "where did that come from?" — researchers, students, analysts, writers, and people preparing to teach something they have just learned.

The one rule worth learning first Deeper Notebook answers from your sources. If your sources do not support an answer, it is designed to say so rather than fill the gap. When an answer feels thin, the fix is almost always to add a better source — not to rephrase the question.

2Installing and first launch

One drag, one right-click, then about a minute and a half of setup.

Install on macOS

  1. Download Deeper-Notebook-mac-<arch>.dmg from the Releases page.
  2. Open the disk image and drag Deeper Notebook into Applications.
  3. Right-click the app and choose Open the first time. The build is signed but not notarized, so a plain double-click will be refused by Gatekeeper. You only have to do this once per fresh download.
  4. Approve the file-access prompt when macOS asks. The application needs it to read the documents you add and to write its own data folder.

What happens on first launch

The first launch does real work before it shows you anything, and it is slower than every launch after it. In order, it:

  • unpacks its bundled Python runtime, database engine, and web server;
  • builds a private environment for itself under your home folder;
  • downloads the local model files it needs;
  • starts nine or more background services, each on a port it picks at launch;
  • checks that each one answered, and opens the window.

Budget roughly 90 seconds the first time. Later launches skip the unpacking and the downloads. If a launch feels slow, §26 shows you where the time went.

Windows Windows builds are produced separately — releases carry Deeper-Notebook-windows-x64.zip and a Setup-x64.exe installer. The screenshots in this guide are from macOS; the interface is the same.

The setup wizard

On a fresh profile the app opens a short wizard. You can accept every default and change your mind later — nothing there is permanent. The two questions worth answering deliberately:

  • Do you want to add a cloud provider? You do not have to. If you skip it, the app uses its bundled local models for everything.
  • Do you want a sample notebook? Say yes the first time. It seeds a notebook with a source already indexed, so your first chat has something to answer from.

3Anatomy of the workspace

Four regions. Learn them once and every screen reads the same way.

The rail (far left)

Your badge, and a + button that starts something new from wherever you are — a notebook, a source, a note.

The navigation column

Grouped by what you are doing, not by data type:

GroupContainsUse it when
CollectSources, CaptureYou are gathering material
ProcessNotebooks, Knowledge, Ask and SearchYou are working through it
CreateStudio, Podcasts, StudyYou are producing something from it
ManageModels, Transformations, Settings, MCP Servers, Launch Preferences, AdvancedYou are configuring the app

The working surface (centre)

Whatever you selected. In a notebook this splits into three resizable panes — sources │ notes │ chat — and remembers the widths you set.

The Context lens (right)

A running summary of what is in play: the evidence behind the current view, backlinks, and what the assistant currently has in context. When you are unsure why an answer said what it said, look here first.

Two controls in the top-right corner

  • Quick actions (⌘K) — the command bar. Type to jump to any notebook, source, or setting. This is the fastest way to move around the app.
  • Focus mode (⌘⇧F) — hides the navigation and the lens and leaves you with the working surface alone.
Both work from the keyboard You never have to reach for either button. ⌘K opens Quick actions from anywhere, ⌘⇧F toggles Focus mode, and Esc leaves it again.

4Home

Where you left off, and whether the machinery is healthy.

Home is deliberately quiet. It shows three things:

  • Continue — the notebook and question you were last working on.
  • Quick actions — start a Studio artifact, or open a new empty notebook.
  • Runtime status — whether the API, the database, and the migrations are ready.

Reading the runtime status panel

ReadsMeansDo
ReadyEverything answered its health checkNothing
StartingA service is still coming up — normal for the first minuteWait
DegradedSomething optional did not start — often a local modelOpen Settings → Local models and check which one

Degraded is not broken. The application is designed so an optional service failing never stops you working — it removes a capability, tells you, and carries on. If your chat model is the thing that is degraded, you will get an explicit message rather than a silent hang.

Use Refresh runtime status after you start or stop a model; the panel does not poll aggressively, on purpose.

Startup timings

If a launch felt slow, the app records how long each stage took and surfaces any stage over a tenth of a second. You do not need to open a log file to find out that model loading, not the database, was what you waited for.

5Notebooks

A notebook is a question and the material that answers it.

Creating one

  1. Click + in the rail, or open Notebooks and use the new-notebook action.
  2. Give it a name that states the question, not the topic. "Does creatine help endurance?" beats "Creatine" — it makes it obvious later which sources belong.
  3. Add a one-line description. It is what the assistant sees when it needs to know what this notebook is for.

Archiving instead of deleting

Archive hides a notebook from the index without touching anything inside it. Delete is permanent and cascades: sources, notes, the passage index, and the chat sessions all go with it.

Delete is not undoable from inside the app Your safety net is the automatic backup (§25), not an undo button. If you are unsure, archive.

The notebook workspace

Four actions live in the header:

ActionWhat it does
Mind mapOpens a graph of this notebook and everything related to it (§10)
ArchiveHides it from the index; fully reversible
ExportWrites the notebook and its notes out as Markdown
DeletePermanent, and cascades to everything inside

Guided research

Type what you want to investigate and press Start research. The app searches, shows you candidate sources, and waits for you to approve each one before importing it. Nothing is added to your notebook without you clicking. This is deliberate — an unattended importer would quietly fill your notebook with material you never read.

6Sources — adding material

Everything the application knows, it knows because you added it here.

What you can add

KindFormatsHow it is read
DocumentsPDF, DOCX, PPTX, XLSX, Markdown, plain textText extraction, 50+ formats supported
AudioMP3, WAV, M4A and similarTranscribed by a local speech-to-text model
VideoMP4, MOV and similarAudio track transcribed; frames used for the cover
Web pagesAny URLFetched and cleaned; dynamic pages rendered if the optional engine is installed

Adding a source

  1. Open a notebook, or the Sources page.
  2. Drop a file onto the sources pane, or use Add source and paste a URL.
  3. Watch the state on the card. It moves Queued → Processing → Ready.
  4. Wait for Ready before you ask about it. A source that is still processing has not been indexed yet, so chat cannot see inside it.
Why a big PDF takes a moment Adding a source is not a copy. The app extracts the text, splits it into passages, and computes a numeric index for every passage so it can find the right one later. A long document does real work here. It only happens once.

Discover sources

Inside the Sources panel, Discover searches the web for a topic, shows you the candidate pages, and lets you add the ones you want as link sources. This only reaches the network if a search provider is available — and one always is, because Wikipedia needs no key. Configure a better provider in Settings if you want broader results (§17).

Enrichment on ingest

Two optional switches in Settings → Sources, both off by default:

  • Auto-summarise — writes a Summary insight and a one-line preview onto the card as soon as the source is ready.
  • Extract key topics — pulls topic tags from the content so you can filter by them later.

Both cost a model call per source. Turn them on when you are adding a lot of material you will need to skim later; leave them off when you are adding a handful of things you will read yourself.

7Reading a source

The reading pane is also where citations land.

What is on this screen

  • The content. PDFs render inline, page by page. Everything else shows its extracted text. If a PDF fails to render, the extracted text appears instead — you never lose access to the content.
  • Insights. Anything generated from this source: summaries, key points, extracted topics, and the output of any transformation you ran (§14).
  • Per-source chat. A conversation scoped to this one document. Useful when a notebook has thirty sources and you want to interrogate exactly one.

The context toggle — the most important control here

Each source has three settings that decide what notebook-wide chat may use:

SettingThe assistant seesUse when
OffNothing from this sourceIt is off-topic, outdated, or you are testing what a subset says
Insights onlySummaries and extracted points, not the full textThe source is long and you want its conclusions without spending context on it
FullThe whole indexed documentNormal — this is the default

This is how you conduct an argument with your own library: turn one side off and ask the same question again.

Jumping from a citation

When a chat answer shows a citation pill, clicking it opens that source here and scrolls to the exact passage, highlighted. This turns a citation from a reference you have to trust into a claim you can check in one click.

8Chat — grounded answers

The centre of the application. Everything else feeds it.

Chat lives in the right pane of a notebook. Ask a question and the application does five things before the model ever sees your message:

  1. Recalls what it has learned about you from earlier conversations.
  2. Retrieves the passages from your sources most likely to answer the question.
  3. Checks the network. If you are offline, or you have switched offline mode on, it swaps any cloud model for the best local one rather than hanging on an unreachable service.
  4. Attaches its tools — web search, scholarly search, add-a-web-page, and any MCP servers you configured.
  5. Asks the model, and if the model calls a tool, runs it and asks again — up to four rounds.

Reading an answer

  • Citation pills mark grounded claims. Click one to jump to the passage (§7).
  • "Using X of Y sources" sits above the input. Click it to see exactly which sources are in context right now. If an answer ignored something you expected, check here before blaming the model.
  • "Answered with <model> (offline)" appears on any message that was routed to a local model because the network was unavailable.

Tools

ToolWhat it doesNeeds
Web searchSearches the live web and cites what it foundNothing — Wikipedia is always available. A provider key gives better results
Scholarly searchSearches OpenAlex and arXiv for papersNothing
Add web sourceTurns a page it found into a permanent source in your notebookNothing
MCP serversAnything you connect (§20)Configuration

The picker row above the input turns individual tools off for a conversation. Turn web search off when you want an answer strictly from your own library.

If your local model cannot use tools Many small local models do not support tool calling. The application detects this and answers without tools rather than failing. You will get a normal reply — just one that could not search the web. Switch to a larger local model or a cloud model if you need tools.

Memory

The application extracts durable facts and preferences from your conversations and recalls them later — so you do not re-explain your project every session. It is bounded on purpose: it keeps a capped number of items, only stores things it is reasonably confident about, and sanitises what it stores so text inside a source cannot instruct it. Memory settings live in Settings.

Debate mode

The Debate toggle above the chat input, next to the tool picker, changes how the model responds to your next message — not what it can see. With it on, the assistant argues the opposing position: it steelmans the case against your claim, concedes when your sources genuinely support you rather than manufacturing disagreement, and still cites every assertion back to your sources exactly as it does in standard chat. It is a good way to stress-test a conclusion before you commit to it in writing.

The toggle is per-turn, not a setting — it does not persist across a new session, and it does not change retrieval or which sources are in context, only the stance the model is asked to take.

9Ask and Search

Two different questions, two different tools.

SearchAsk
Answers"Where did I read about X?""What does everything I have say about X?"
ReturnsRanked passagesOne synthesised, cited answer
ScopeYour whole libraryThe notebook
CostInstant, no model callA model call

Search matches on meaning, not just words — a passage about "resting heart rate declining" will come back for "cardiovascular adaptation" even with no shared vocabulary.

Ask declines. If your sources do not support a grounded answer, Ask says so instead of producing a plausible synthesis from nothing. Treat a declined Ask as information: it is telling you your library has a gap.

10Knowledge and the mind map

Your library as a structure rather than a list.

Knowledge projects your material as documents, blocks within them, and the relations that connect them. It is where you go when you want to see how things sit together rather than read one thing.

The mind map

From any notebook header, Mind map draws a radial graph: the notebook at the centre, its sources and notes around it. Click a node to open it. The graph is built from relations that already exist in your data — it is a view, not a separate thing you have to maintain.

Vault sync

If you keep a Markdown vault — Obsidian, Logseq, or plain folders of Markdown — Deeper Notebook can watch it and keep your notes in step. Notes you write in the app appear as files; files you write outside appear as notes. The first pass over a large vault is proportional to its size; after that it watches for changes.

Turn a notebook into something you can hand to someone.

Producing one

  1. Select the sources to draw from. They must all be Ready. If any are still processing, generation stops and tells you which — this is deliberate, because a half-indexed source produces a thin artifact that looks finished.
  2. Choose the artifact type.
  3. Add direction if you have any — audience, angle, length.
  4. Generate, and watch the approval gates: context building, privacy review, model routing, generation.
  5. Review the result. Edit it in place if you want; edits are re-checked and the exports are regenerated so the files never disagree with what you see.

Where the files go

Artifacts save under your knowledge folder, in an evidence-studio directory, unless you have configured a different export path. Slide decks and infographics write their visual files next to the Markdown and JSON. All rendering happens locally — nothing is sent to a hosted office or image service.

Video Overview

Pair a finished slide deck with a finished, timestamped audio overview and the app composes a captioned 1920×1080 video locally, writing an .mp4 and a .vtt caption file. It verifies the result before it offers it to you.

12Podcasts

A multi-speaker audio conversation about your sources — with the outline under your control.

Generating an episode

  1. Choose the notebook and the sources.
  2. Choose an episode profile (the format) and speaker profiles (the voices and personas).
  3. Set length — short, medium, or long. This controls how many segments the outline gets.
  4. Set the language if it is not English.
  5. Optionally add focus instructions: what to emphasise, what to skip.
  6. Decide whether to review the outline before audio — see below.
  7. Generate.

The stages

Generation runs through named stages with live progress: outline → transcript → audio → combining. A Cancel button is available throughout.

Always review the outline the first time With outline review switched on, generation pauses after the outline. You can rename segments, rewrite their descriptions, and change each one's size before any audio is synthesised. Audio is the expensive stage — fixing the structure before it is the single highest-value habit in this feature.

Retrying and regenerating

Your instructions are stored with the episode and replayed on retry, so a retry is not a blank slate. A completed episode can be regenerated with different settings without re-selecting the sources.

If it fails immediately

Selections that exceed the content budget are rejected at submit time rather than failing halfway through. If that happens, remove a source or use insights-only on your longest one.

13Study

Scheduled review, so what you collected stays learned.

How the scheduling works

Study uses FSRS, a spaced-repetition scheduler. After each card you say how it went; FSRS models how quickly you forget that specific card and schedules it for the moment you are about to. Cards you find easy stretch out quickly. Cards you keep missing come back tomorrow.

The only thing you have to get right is honesty about how well you recalled it. Marking a card easy because you almost got it will push it out of reach.

Getting cards in

  • Generate flashcards or a quiz from a notebook in Studio (§11).
  • Import an existing Anki deck (.apkg).
  • Write them yourself.

Export works the same way — your cards go back out as an Anki deck, so you are not locked in.

Study plans

A plan is a scoped course through a notebook. Open a plan and the study assistant will help you work through it — restricted to that plan's sources. It will not answer from material outside the plan, even if that material is in the same notebook. That restriction is enforced on the retrieval side, not just requested in a prompt.

ExamLab — timed exams

Generate a quiz in Studio (§11), then sit it as a timed exam from Study. Starting an attempt snapshots every question — so if you edit or regenerate the quiz while an attempt is in progress, your exam stays exactly as it was when you started. Grading needs no model call and works fully offline: your answers are compared against the snapshot the moment you submit.

  • While the exam is running you see only the questions and options — never the answer key. The application is built so the answer key cannot appear in your browser early, even under a bug: the "in progress" view of an attempt simply does not carry that field.
  • A late submission is still graded, just marked late — the clock is a guide, not a lockout.
  • "Add missed questions to Study" turns each wrong answer into a flashcard, scheduled by the same FSRS engine as the rest of Study. Run it again after a re-take and it only adds cards for misses it has not already seeded — you will not end up with duplicates.

14Transformations

A saved instruction you can run over any source, plus a way to make it better.

A transformation is a named prompt — "summarise for a sceptical reader", "extract every claim with a number in it", "list the methods and their sample sizes". Run it over a source and the output is saved as an insight on that source.

Cornell Notes ships as one of the built-in transformations: a cue column of recall questions, a note column of substance, and a summary at the bottom — the format students already know from class. It runs like any other transformation and is safe to edit or delete; it is only ever installed once, on first launch, and never overwrites a transformation you have changed.

Writing a good one

  • Say what the output should look like, not just what to do. "A bulleted list, one claim per bullet, each with the page it came from" beats "extract the claims".
  • Say what to do when the source does not contain what you asked for. Otherwise the model invents.
  • Keep one transformation to one job. Chaining two small ones is easier to debug than fixing one large one.

The prompt optimizer

Each transformation card has an Optimize action. It genuinely trains the prompt:

  1. You pick a notebook to train against and describe, in plain English, what a good output looks like.
  2. Each round runs the prompt over example sources.
  3. A second model scores the outputs against your criteria.
  4. The optimizer proposes a bounded edit to the prompt.
  5. The edit is kept only if it improves results on examples it was not trained on.
  6. You see the before and after side by side, and it is applied only when you click Apply.

It can run entirely against your local model, so nothing leaves the machine.

15Capture

A folder that becomes sources.

Nominate a folder as a capture root and the application watches it. Anything you drop in appears in the capture inbox, where you decide which notebook it belongs to before it becomes a source.

This is the right tool when material arrives faster than you can file it — scanned pages, downloads, recordings from a meeting. It keeps the arrival step and the filing step separate, so a busy week does not turn into an unusable notebook.

16Advanced

Diagnostics and the tools you reach for rarely.

Advanced carries what you need when something is wrong or you are curious about the machinery: detailed runtime state per service, backup provenance, and maintenance actions. Nothing here is required for normal use. It is worth knowing it exists before you need it.

17Settings

Where behaviour is decided.

Models

Choose which model does what: chat, embedding (the passage index), transcription, and speech. You can mix — a cloud model for chat and local models for everything else is a common and sensible setup.

Changing the embedding model re-indexes everything The passage index is built by a specific model, and indexes from different models are not comparable. Switching it means rebuilding, which on a large library takes minutes. Pick one early and stay on it.

Sources

The two enrichment switches described in §6, and extraction preferences.

Network

  • Offline mode. Force everything local even when you have a connection. Useful on a metered link, on someone else's network, or when working with material you would rather not send anywhere.
  • Smart routing. Optional. Picks local or cloud per turn, based on how much context the turn needs and whether your local model is healthy.
  • Search providers. See below.

Search providers, in the order they are tried

#ProviderKeyNotes
1SerperRequiredPaid, fast, broad
2TavilyRequiredPaid, research-oriented
3BraveRequiredPaid, independent index
4SearXNGNoneSelf-hosted; the app ships one you can run
5WikipediaNoneAlways available — search works out of the box

Each provider is tried in turn until one answers. You never have to configure search for it to work; adding a key makes it better.

Privacy

With the privacy gate on, any turn containing detected secrets or personal information is kept on your local model rather than being sent to a cloud provider. When that happens you get an On-device badge and an explicit "Re-ask allowing cloud" action, so the decision stays yours and is never made silently.

18API keys and credentials

Optional, encrypted, and reversible.

Cloud providers are opt-in. Adding a key here makes that provider's models available in the model picker; adding none is a fully supported configuration.

Supported: OpenAI, Anthropic, Google, Groq, Mistral, DeepSeek, and Ollama for models you run yourself. Search provider keys are configured here too.

How keys are stored

Encrypted in the database using an encryption key that belongs to you. They are never written to a log file, never included in an error message, and never displayed back to you after you save them.

Rotating your encryption key

You can supply a new key alongside the old one and the application re-encrypts in place — you do not have to re-enter a dozen provider keys. That capability exists precisely because the alternative guarantees nobody ever rotates.

Removing a provider

Delete the credential. Its models disappear from the picker. Nothing else changes — your notebooks, sources, and index are untouched, because they never depended on that provider.

19Local models

The part that makes offline real.

The three ways to have a local model

KindHow to add oneNotes
GGUFPut a .gguf file in the GGUF model folderBroadest compatibility; the bundled default
MLXPut a complete MLX repository in the MLX model folderApple Silicon only; usually faster
Ollamaollama pull <name>Detected automatically if Ollama is running

Files appear in the picker on the next launch. The GGUF Manager can download models for you and swap the active one without restarting.

Reading this screen

  • Model library — what is installed. Read-only; use Rescan local library after adding files.
  • Readiness — only models that pass verification are eligible for automatic routing. A model that is present but not ready will not be picked silently.
  • Role routes and overrides — which model does which job. Overrides are explicit, and are rejected if the model fails a readiness, quality, context, or memory gate. The app will not quietly route work to a model that cannot do it.
Keep each runtime's model folder separate If Ollama's storage shares a directory tree with your GGUF and MLX files, every scan re-inventories all of them. Separating them took one measured operation from 10–15 seconds down to 22 milliseconds.

Choosing a size

Bigger models are better and slower, and a very large model loading from disk for the first time can take up to a minute. If chat feels sluggish, try a smaller model before assuming something is broken.

20MCP servers

Give the assistant abilities the application does not ship with.

The Model Context Protocol is a standard way for a tool server to describe what it can do. Connect one here and its tools become available to chat, alongside the built-in ones.

Adding a server

  1. Add the server's address and any credentials it needs.
  2. The application connects and lists the tools it offers.
  3. Those tools now appear in the chat tool picker, where you can turn individual ones off.
An MCP server can act on your behalf Only connect servers you trust. A tool server can do whatever it advertises — read files, call APIs, change things. The application will not second-guess a server you explicitly configured.

If a server is unreachable, chat continues without its tools rather than failing. A broken integration costs you a capability, not a conversation.

21Launch preferences

What starts, and how.

This screen controls the launcher rather than the application: which local model to load at startup, how patient to be with services that are slow to come up, and where the data folder lives.

If you delete a model file, clear it here too Pointing the launcher at a model that no longer exists used to fail quietly. It now refuses clearly and continues the launch without that provider — but the fix is still to pick an existing model here.

Ports are chosen fresh at each launch, so there is nothing to configure and nothing to collide with.

22Themes and appearance

Seventeen themes, all of them accessible.

Every theme meets WCAG AA or AAA contrast. These are not decoration — a high-contrast theme is the difference between usable and not for some readers, and the paper themes are noticeably easier for long reading sessions.

Density

Comfortable is the default and gives text room to breathe. Compact tightens spacing so more fits on screen. The setting persists across launches.

Motion

Animation is limited to effects that do not move layout, and is disabled entirely if your system is set to reduce motion. You do not have to configure anything for that to take effect.

23Working offline

Not a degraded mode. The design centre.

With local models configured, everything below works with no network at all:

  • Adding and indexing sources, including transcribing audio and video
  • Chat, with citations
  • Ask and semantic search
  • Memory recall and extraction
  • Studio artifacts
  • Podcast generation, including the audio
  • Study scheduling

Only live web search and cloud models require a connection — and web search falls back to whatever providers are reachable.

The two ways you end up offline

  • By circumstance. The application notices and substitutes a local model for any turn that was going to a cloud provider. You see an amber badge in the shell and a note on the affected message. It does not hang waiting for a service that is not there.
  • By choice. Switch offline mode on in Settings → Network and it behaves that way even with a working connection.
One case where it stops rather than substitutes If you are offline, the turn needs a cloud model, and you have no local model configured at all, the application fails immediately with a message telling you why — instead of waiting minutes on an unreachable endpoint. Configure a local model and this never happens.

24Privacy — what leaves your machine

A short and checkable list.

Never leaves

  • Your notebooks, sources, and their full text
  • The passage index
  • Your chat history
  • What the assistant remembers about you
  • Your API keys and encryption key
  • Studio artifacts, slide decks, infographics, and video overviews — all rendered locally

Leaves only when you cause it to

  • A cloud model call — sends your message plus the source passages that were retrieved for it, to the provider whose key you added.
  • A web search — sends the search query to the provider being tried.
  • Adding a web source — fetches the URL you gave it.
  • An MCP tool call — sends whatever that tool takes, to the server you configured.
  • A model download — fetches the file from Hugging Face.
  • The update check — asks the releases page whether a newer version exists.

Three switches that shrink the list

  1. Use local models only. Removes cloud model calls entirely.
  2. Offline mode. Removes cloud calls and search.
  3. The privacy gate. Keeps any turn containing detected secrets or personal information on your local model even when cloud is otherwise in use — with an explicit consent action if you want to override it for that turn.

Every outbound address the application resolves is checked before it is used, and requests to your own machine's private network from a source URL or a model-directed fetch are refused.

25Backups and recovery

Automatic, verified, and worth testing once.

Automatic backups

The application exports your database on an interval and keeps a rolling set of recent exports. Each backup is written atomically — a backup interrupted halfway never replaces a good one — and carries a manifest of checksums so a corrupted file can be identified as corrupted rather than silently restored.

Restoring

Verify a backup first, then restore it. Verification checks the contents against the manifest. If it fails, use an older backup — restoring a bad one is worse than being a day behind.

Self-healing

If the application is force-quit, the database can be left in a state that will not open. It detects this on the next launch, takes a backup first, and repairs. A Repair & restart button handles the relaunch for you.

Test a restore once, on purpose A backup you have never restored is a hypothesis. Do it once when nothing is wrong, so you know how it feels before the day you need it.

28Where your data lives

One folder. Know it, back it up, and never delete it.

Everything the application owns lives under a single folder in your home directory:

PlatformLocation
macOS and Linux~/.deeper-notebook/
Windows%USERPROFILE%\.deeper-notebook

Inside it: the database, your uploaded files, conversation checkpoints, logs, backups, the private Python environment the app built for itself, and the startup receipt.

Never delete this folder as part of an uninstall or a cleanup Deleting the application removes the program. Deleting this folder removes your work. They are separate on purpose.

Moving to another machine

Install the application on the new machine, then restore a verified backup (§25). Do not copy the folder by hand — parts of it, including the private Python environment, are specific to the machine that built them.
