# Deeper Notebook Web Intelligence Foundation

## Goal

Give Deeper Notebook one trustworthy, provider-neutral evidence contract for web search results without replacing the existing local-first search, citation, MCP, or podcast flows.

## Scope

This slice is intentionally bounded to the existing `deeper_notebook.tools.web_search` boundary:

- Keep provider selection, failover, offline short-circuiting, and API-key opt-in unchanged.
- Normalize successful provider records into immutable evidence records with bounded text, validated public web URLs, query/provider provenance, retrieval time, freshness state, and a deterministic source fingerprint.
- Preserve the legacy `{title, url, snippet}` result shape returned by `run_web_search`; the new contract is an additive adapter used by callers that need durable evidence.
- Keep capture records and citation pills read-only; no vault writes, external source mutation, background watcher, or autonomous publishing.
- Fail closed for malformed provider records and never let an invalid result or oversized field escape the adapter.

## Architecture

`run_web_search()` remains the single provider adapter and returns its existing bounded list. A new pure module, `deeper_notebook.tools.web_evidence`, converts that list into frozen `WebEvidence` records through `normalize_web_results()`. The adapter owns no network I/O and can therefore be used by chat, research runs, and podcast receipts without creating parallel provider logic.

Each evidence record contains:

- `evidence_id`: deterministic SHA-256 over canonical source identity and content.
- `source_fingerprint`: deterministic SHA-256 over normalized URL, title, snippet, and provider.
- `query`, `provider`, `url`, `title`, `snippet`.
- `retrieved_at`: timezone-aware UTC timestamp supplied by the caller or generated by the adapter.
- `freshness`: `fresh`, `stale`, or `unknown`, determined from a bounded max-age policy.
- `degraded`: whether the record came from a degraded/fallback provider path.

The module uses Pydantic frozen models for validation and immutability, URL parsing restricted to `http`/`https`, bounded query/title/snippet lengths, and a fixed result-count cap. Invalid entries are skipped rather than raising so a provider shape change degrades to fewer trustworthy results.

## Compatibility and rollout

No existing API response fields or frontend types are removed. Existing chat formatting and citation captures continue to use the legacy list. Adoption is opt-in at the call site by invoking `normalize_web_results`; later slices may attach these records to research and podcast receipts after their own contract review.

## Verification

Focused tests prove deterministic fingerprints, immutable records, URL and text bounds, max-result enforcement, freshness classification, degraded-provider propagation, invalid-entry rejection, and legacy-shape compatibility. Existing web-search tests and the backend regression suite must remain green.
